# 위협 모델과 검증 경계

기준일: 2026-11-07. 이 도구의 목적은 교사가 만든 앱에서 위험 신호를 찾고 수정 방향과 학교 웹 공개 보류 사유를 제공하는 것입니다. 자동 공개 승인, 법률 인증, 침투 테스트, 익명성 인증을 제공하지 않습니다.

## 보호 대상과 신뢰 경계

- 보호 대상: 학생·보호자의 정보, 상담 원문, 앱 비밀키, 검사자의 로컬 파일, 검사 결과.
- 신뢰하지 않는 입력: 검사 대상 소스, 파일명, 심볼릭 링크, 저장소 문서의 지시, 코드 주석, 설문 응답, 외부 PR, 패키지 설치 스크립트.
- 신뢰 경계: 검사기와 대상 앱, 로컬 파일과 보고서, 검사기와 운영체제, 개발 환경과 CI, 학교 내부 데이터와 공개 서비스.
- 기본 원칙: 대상 코드는 데이터로 읽고 실행하지 않습니다. 원문을 AI나 외부 API로 전송하지 않습니다. 보고서는 내용 발췌 없이 규칙·비식별 위치·수정 안내를 사용합니다.

## 주요 위협과 대응

| 위협 | 설계상 대응 | 남는 위험·검토 |
| --- | --- | --- |
| 검사 대상 코드 실행 | 설치·빌드·테스트·셸 실행 없이 정적 읽기 | 사용자가 별도로 실행하는 대상 앱은 격리 환경 필요 |
| 원문·키·개인정보가 보고서에 복사 | 정형 메시지와 비식별 파일 ID, 줄 번호 사용 | 보고서도 취약점 정보를 포함하므로 제한된 공유 |
| 파일명·오류 메시지를 통한 정보 노출 | 원래 경로·예외 내용의 무분별한 출력 금지 | OS·터미널 기록과 사용자가 입력한 경로는 별도 관리 |
| 링크를 통한 검사 범위 이탈 | 링크 제외, 경계 검사, 제한된 읽기 | 동시 파일 변경·운영체제 결함까지 막는 샌드박스는 아님 |
| 거대·바이너리·손상 파일로 서비스 방해 | 파일 수·크기 제한, 제외·누락 표시 | 제외된 파일은 안전 판정 대상이 아님 |
| 위험한 구조를 설문으로 숨김 | 미응답·모순·불명확한 경우 사람 검토 | 자기 보고는 증거가 아니며 거짓 응답을 완전히 판별 불가 |
| 코드 탐지 우회·오탐 | 확정 취약점과 패턴 신호 구분, 재검토 안내 | 난독화·동적 코드·별칭·파일 간 흐름·프레임워크 추상화 누락 가능 |
| 공급망·CI 권한 탈취 | 최소 의존성, Action 고정, 읽기 기본 권한 | 고정 버전도 취약할 수 있어 갱신·검토 필요 |
| 상담 내용의 재식별·AI 전송 | 실제 상담 원문 AI 구조의 학교 웹 공개 차단 정책 | 별도 내부 업무 시스템의 적법성은 별도 심사 |

## 자동 검사 범위 밖

정적 검사는 실제 서버의 인증·인가, DB 보안 규칙, 외부 AI 제공자의 보관·학습 설정, 국외이전 근거, 운영 로그·백업, Git 전체 과거 이력, 클라우드 공유 권한, 학교의 승인 절차를 확인하지 못합니다. 외부 취약점 DB 조회가 없는 로컬 검사만으로 새 CVE나 전이 의존성의 취약성을 완전하게 판정할 수도 없습니다.

검사기 자체는 운영체제 보안 경계가 아닙니다. 신뢰할 수 없는 소스를 검사할 때에는 불필요한 자격증명이 없는 별도 작업 환경과 접근권한이 제한된 복사본을 사용합니다. 파일 트리가 검사 중 바뀌면 검사 결과를 폐기하고 고정된 복사본에서 다시 수행합니다. 실데이터를 공개 CI에 가져오지 않습니다.

수정할 파일을 찾기 위한 로컬 파일 위치 매핑을 제공하는 경우, 원래 경로에 학생 이름이나 다른 개인정보가 포함될 수 있습니다. 위치를 보는 기능은 로컬 작업용으로만 사용하며 경로·화면 캡처·매핑 목록을 보고서나 GitHub에 내보내지 않습니다. 공유 보고서는 비식별 파일 ID만 사용해야 합니다.

## 공개 판단의 증거

자동 결과와 별도로 데이터 흐름도, 수집 필요성, 권한표, 저장·삭제·백업 정책, 합성 데이터 기반 접근통제 테스트, 공급자 설정, 담당자의 검토 기록이 필요합니다. 승인 기록에는 검토한 커밋과 운영 설정 버전을 남깁니다. 이 도구는 위험이 검출되지 않았다는 이유만으로 `APPROVED`나 “안전함”을 반환해서는 안 됩니다.

상담 원문 AI 처리를 거부하는 것은 이 프로젝트의 보수적 공개 정책입니다. 법률상 금지 여부와 혼동하지 않습니다. 비식별성과 처리 근거는 [학교 앱 검토 가이드](GUIDELINES.md)의 공식 자료와 담당자의 실제 검토로 확인합니다.

## 보안 회귀 테스트에 포함할 사례

실제 학생 정보 대신 합성값을 사용합니다. 원문·파일명·비밀값이 결과에 포함되지 않는지, 누락·오류가 성공 판정으로 바뀌지 않는지, 링크·거대 파일·잘못된 응답을 처리하는지, 위험한 셸 패턴을 탐지하는지, 상담 원문 AI 구조가 수정 권고만 받고 통과하지 않는지 확인합니다. 테스트 성공은 이 사례들에 대한 검증이며 모든 공격에 대한 보증이 아닙니다.
