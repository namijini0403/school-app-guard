# 학교 앱 공개 전 검토 가이드

기준일: 2026-11-07 (대한민국). 이 문서는 이 도구의 보수적인 **학교 웹 공개 정책**입니다. 법률 위반 여부를 자동 판정하거나 개인정보 보호책임자의 검토를 대신하지 않습니다.

## 결과를 읽는 방법

| 결과 | 교사가 할 일 |
| --- | --- |
| `BLOCKED` | 현재 구조로 학교 웹에 공개하지 않습니다. 원문 처리·외부 전송 구조를 바꾼 뒤 다시 검토합니다. |
| `REMEDIATE` | 안내된 취약점 또는 위험 신호를 확인하고 수정합니다. 수정한 버전을 다시 검사합니다. |
| `REVIEW_REQUIRED` | 자동 검사가 안전을 증명하지 못합니다. 누락된 증거와 운영 설정을 담당자가 확인합니다. |

탐지 건수가 0이어도 공개 승인이나 익명성 인증이 아닙니다. 정적 검사는 실행 중인 서버, 실제 데이터베이스, 접근권한, 백업, Git 과거 이력까지 검증하지 못합니다. 코드의 위험 신호는 실제 공격 가능성과 구분하여 확인합니다.

## 상담 원문을 AI가 분석하는 앱

> 학생을 돕기 위한 목적은 이해합니다. 하지만 실제 상담 기록에는 건강, 가족관계, 사건, 친구 관계처럼 학생을 알아볼 수 있는 맥락이 남습니다. 이름을 지워도 같은 반 사람은 누구인지 알아볼 수 있고, AI 요청·응답·오류 로그·백업에도 내용이 남을 수 있습니다. 따라서 이 도구의 정책에서는 실제 학생 상담 원문을 AI로 분석하는 현재 구조를 학교 웹에 공개할 수 없습니다. 학생 원문을 받지 않는 교육용 기능으로 바꾸고 다시 검토해 주세요.

이 정책은 모든 상담 지원 시스템이 법적으로 금지된다는 뜻이 아닙니다. 별도 내부 업무 시스템의 도입 가능성은 학교·교육청의 권한, 처리 목적과 근거, 민감정보 처리 요건, 위탁·국외이전 여부, 접근통제 등을 별도로 검토해야 합니다. 동의 체크박스나 API의 학습 미사용 설정 하나만으로 공개 허용으로 바꾸지 않습니다.

대체 설계는 다음 순서로 선택합니다.

1. 실제 기록과 무관하게 만든 합성 사례와 일반 상담 자료만 사용합니다. 합성 사례를 만들려고 실제 원문을 외부 AI에 입력하지 않습니다.
2. 공개 앱은 일반 자료 탐색과 교사용 체크리스트에 한정합니다. 자유 서술 입력창으로 실제 상담 내용이 다시 들어오지 않도록 설계합니다.
3. 개인 단위 기록 없이 필요한 통계만 사용합니다. 소수 집단·희귀 사건은 합치거나 제외하고, 공개된 정보와 결합했을 때 재식별되는지 검토합니다.
4. 필요한 내부 업무는 공개 앱과 계정·저장소·권한·운영 환경을 분리하여 별도의 승인 절차로 다룹니다.

## 최소 비식별 처리에서 확인할 것

이름을 학생 번호나 별명으로 치환하는 **가명처리**와, 합리적인 수단으로 다른 정보와 결합해도 사람을 알아볼 수 없게 하는 **익명처리**는 다릅니다. 자동 정규식 검사는 익명성을 보증할 수 없습니다. 법의 적용 제외 기준은 단순 이름 삭제보다 엄격합니다. [개인정보 보호법 제58조의2](https://law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1022694479)

- 직접 식별자: 이름, 학번, 연락처, 계정, 주소, 보호자 정보, 얼굴·음성, 사진 메타데이터를 검토합니다.
- 간접 식별자: 학교·반·학년, 날짜, 희귀한 사건, 가족 구성, 구체적 장소를 조합하여 누구인지 알 수 있는지 검토합니다.
- 자유 서술: 이름이 없어도 사건 설명 자체가 식별자가 됩니다. 마스킹 결과만 믿고 상담 원문을 공개하지 않습니다.
- 연결 정보: 원본과 가명 값의 대응표는 공개 산출물에 포함하지 않고, 필요할 때도 별도 권한으로 관리합니다.
- 전체 흐름: 입력, 서버, AI 제공자, 응답, 분석 서비스, 오류 추적, 백업, 내보내기 파일에서 같은 기준을 확인합니다.

개인정보위의 2026년 개정 안내는 사전 준비, 위험성 검토, 가명처리, 적정성 검토, 안전한 관리로 이어지는 절차를 설명합니다. 처리 대상과 환경에 따른 검토가 필요합니다. [2026년 가명정보 처리 가이드라인 개정 안내](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&mCode=C020010000&nttId=11928) 교육 환경의 세부 검토에는 [교육분야 가명·익명정보 처리 가이드라인](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS217&mCode=D010030000&nttId=10425)을 함께 사용합니다.

## 검사 → 수정 → 재검토

1. **로컬에서 시작합니다.** 앱 소스의 검토용 복사본을 사용하고 운영 DB, 학생 원문, 비밀키를 검사 도구나 GitHub에 업로드하지 않습니다. 검사 대상의 설치·빌드 스크립트는 실행하지 않습니다. 검사 범위에서 제외된 데이터가 있다면 담당자가 안전한 환경에서 별도 검토합니다.
2. **구조 질문에 사실대로 답합니다.** 무엇을 수집하고 어디로 보내며 누가 조회하는지 확인합니다. 모르는 항목은 안전하다고 답하지 않습니다.
3. **문제별 수정 증거를 남깁니다.** 실제 학생 사례 대신 합성 데이터로 수정 전 실패·수정 후 차단을 확인합니다. 보고서에는 원문을 붙이지 않고 규칙 ID, 비식별 파일 ID, 줄 번호, 수정 커밋, 재검사 결과를 남깁니다.
4. **수정한 버전으로 재검사합니다.** 결과가 해결되지 않았다면 입력 경로, 저장, 전송, 로그 등 빠진 흐름을 점검하고 반복합니다. 경고를 숨기는 것으로 해결 처리하지 않습니다.
5. **담당자가 운영 증거를 확인합니다.** 다른 교사 계정으로 학생 자료를 열 수 없는지, 공개 URL·공유 링크·검색엔진·정적 번들에 데이터가 없는지, 보관기간과 삭제·백업 정책이 지켜지는지 확인합니다.
6. **공개 이후에도 다시 검토합니다.** 새 데이터 항목, AI 제공자, 플러그인, 패키지, 권한, 저장소 설정이 바뀌면 재검토합니다.

| 위험 | 권장 수정 방향 | 확인할 증거 |
| --- | --- | --- |
| 요청 본문·학생 기록을 로그에 출력 | 원문 로깅 제거, 허용한 비민감 메타데이터만 기록 | 합성 민감값이 정상·오류 로그 모두에 없는 테스트 |
| 공개 저장소·브라우저 코드의 키 | 키 즉시 폐기·교체, 서버 측 비밀 저장소 사용 | 이전 키 사용 불가, 프런트 번들에 새 키 없음 |
| 로그인만 있고 학생별 권한 없음 | 서버에서 요청마다 교사·학생 관계 검증 | 다른 계정·다른 학생 ID 조회가 거부되는 테스트 |
| 명령 문자열에 사용자 입력 결합 | 셸 제거, 고정 실행 파일과 인자 배열, 옵션 허용목록 사용 | 메타문자·옵션·경로 조작 입력이 실행되지 않는 테스트 |
| DB·파일·백업 공개 접근 | 기본 거부, 최소 권한, 만료되는 공유, 백업 권한 분리 | 비로그인·다른 사용자 접근 거부 |
| 상담 원문 AI 처리 | 원문 수집·전송 제거, 합성 사례·일반 자료로 재설계 | 원문 입력 경로와 외부 전송 경로가 제거된 설계·테스트 |

## Node.js와 개발 도구 보안

`exec()`나 `shell: true`에 신뢰할 수 없는 값을 전달하면 명령 실행으로 이어질 수 있습니다. `spawn()`·`execFile()`에서 셸을 사용하지 않아도 실행 파일 선택, 옵션 주입, 경로 접근을 따로 제한해야 합니다. 검사에 걸리지 않았다는 사실만으로 안전하다고 판단하지 않습니다. [Node.js child_process 문서](https://nodejs.org/api/child_process.html)

2026-11-07 현재 Node.js는 22·24·26 계열의 HIGH 심각도 문제를 다루는 **11월 11일 이후 보안 릴리스 예정**을 공지했습니다. 예정된 패치를 이미 설치했다고 기록하면 안 됩니다. 실제 릴리스가 나오면 지원되는 계열의 패치 버전을 적용하고 재검사합니다. [Node.js 보안 릴리스 공지](https://nodejs.org/en/blog/vulnerability/november-2026-security-releases)

GitHub에서는 Dependabot, 코드 분석, 비밀 탐지·푸시 보호를 함께 검토합니다. 요금제·저장소 소유 형태에 따라 사용 가능 기능이 다르므로 설정 파일의 존재와 실제 활성화·성공 실행을 구분합니다. 비밀 탐지는 학생 개인정보 검사를 대신하지 않습니다. [GitHub 저장소 보안 시작 안내](https://docs.github.com/en/code-security/getting-started/quickstart-for-securing-your-repository)

CI는 최소 토큰 권한, 검증된 Action의 고정 커밋, 검토되지 않은 PR에 비밀 미제공, 실행 환경 분리를 적용합니다. 의존성 갱신도 검토·테스트하고, 보안 분석 결과에 소스·비밀이 포함될 수 있으므로 공개 아티팩트로 남기지 않습니다. [GitHub Actions 보안 지침](https://docs.github.com/en/actions/reference/security/secure-use)

## 이미 유출된 흔적이 있다면

공개 접근과 추가 전송을 우선 차단하고, 노출된 키를 폐기·교체합니다. 학교의 개인정보 담당자에게 즉시 알려 범위·기간·대상·접근 기록을 제한된 위치에서 확인합니다. 신고·통지 필요 여부와 기한은 담당자가 적용 법령과 사고 사실에 따라 판단해야 합니다. 공개 이슈나 채팅에 원문 증거를 복사하지 않습니다. 파일을 지워도 Git 이력·캐시·복제본·백업까지 사라진 것은 아니므로 별도 정리와 확인이 필요합니다.
