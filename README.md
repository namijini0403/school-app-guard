# 학교 앱 안전 점검 · School App Guard

교사가 만든 앱의 보안·학생 개인정보 위험 신호를 **로컬에서** 확인하고, 한국어로 수정 방향을 안내합니다. 대상 코드를 실행하거나 외부 AI로 보내지 않습니다. npm 의존성·API 키·회원가입이 필요하지 않습니다.

## 실행

지원되는 Node.js 24 이상 최신 보안 패치를 준비하고, 이 저장소에서 실행하세요.

```powershell
node cli.mjs "C:\검토용\앱소스"
```

터미널에 표시된 `http://127.0.0.1:.../#...` 주소를 같은 컴퓨터의 브라우저에서 여세요. 주소의 접근키를 공유하지 마세요. 종료는 `Ctrl+C`입니다. 새로고침하면 접근키가 사라질 수 있으므로 원래 터미널 주소를 다시 사용하세요. 서비스는 외부 인터페이스에 열리지 않습니다.

1. 학생 실데이터·비밀키를 제거한 **정지된 검토용 소스 복사본**을 선택합니다. 운영 DB나 학생 원문을 이 저장소에 복사하지 않습니다.
2. 코드 검사 결과를 읽고 데이터 사용 방식 10개 질문에 답합니다.
3. 수정 방향에 따라 앱을 변경하고 종료 후 같은 명령으로 재검사합니다.
4. 담당자가 실제 접근권한·운영 설정·삭제 증빙을 확인합니다.

소스에 실데이터가 이미 섞여 있을 가능성을 검사하지만, 실데이터를 일부러 가져오도록 요구하지 않습니다. Git 이력·운영 데이터는 승인된 환경에서 별도 검토합니다.

## 결과

| 결과 | 의미 |
|---|---|
| 공개 불가 (`BLOCKED`) | 실제 학생 상담·건강·가정사 원문의 AI 분석 또는 학생 정보 공개 접근 등. 구조 변경 후 재검토 |
| 수정 후 재검사 (`REMEDIATE`) | 셸 실행·비밀값·로그·HTML 삽입 등 위험 신호 또는 부족한 보호 조치 |
| 담당자 확인 필요 (`REVIEW_REQUIRED`) | 자동 검사로 안전을 증명할 수 없음. 누락 범위·운영 증거 확인 |

실제 상담 원문 AI 분석은 이름을 바꿔도 차단합니다. 친절한 이유와 합성 사례·집계·승인된 내부 업무 분리 등 대안을 안내합니다. 이는 이 도구의 학교 웹 공개 정책이며 법률상 일률적 금지 판정이 아닙니다. `APPROVED` 상태는 없습니다.

보고서는 원문·파일명·경로·키 없이 파일 ID와 행 번호를 사용합니다. **파일 위치 확인** 버튼을 누르면 해당 컴퓨터에서만 상대경로를 볼 수 있으며 다운로드 보고서에는 포함되지 않습니다. 이 화면도 외부에 공유하지 마세요. 결과는 서버 메모리에만 유지하며 자동 저장하지 않습니다. 보고서 다운로드는 사용자가 직접 선택합니다.

기계용 출력:

```powershell
node cli.mjs "C:\검토용\앱소스" --json
node --test
```

종료 코드: 1 담당자 확인 필요, 2 수정 필요/실행 오류, 3 공개 불가. 정적 검사만 실행하는 `--json`에는 설문이 포함되지 않으며 구조 차단 판단을 대신하지 않습니다. 승인 성공 코드 0을 반환하는 검사 모드는 없습니다 (`--help` 제외).

## 검사 범위와 한계

셸 실행, 동적 코드, 비밀값 형태, 주민등록번호·연락처·학생 필드, 원문 로깅, 브라우저 저장소, HTML 삽입, 위험한 GitHub Actions 설정과 민감 원문/AI 표현의 동시 존재를 찾습니다. 패턴은 **위험 신호**이며 확정 취약점이 아닙니다. 별칭·난독화·실행 흐름·한국어 이름 전체는 탐지하지 못합니다.

파일 수·파일당 크기·합계 용량·디렉터리 깊이·항목 수·결과 수의 고정 한도가 없습니다. 큰 파일도 끝까지 순차 읽기하며 같은 규칙의 반복 발견도 모두 보고합니다. 읽기 블록마다 64 Ki 문자 문맥을 겹쳐 경계에 걸친 패턴을 검사하지만, 그보다 매우 길게 분리된 표현은 놓칠 수 있습니다. 결과와 로컬 경로 대응은 메모리에 보관하므로 실제 처리량은 컴퓨터 자원과 실행 시간에 영향을 받습니다.

링크·지원하지 않는 형식·읽기 오류·검사 중 변경된 파일은 미검사 범위로 표시합니다. `.git`, `node_modules`, 가상환경은 제외합니다. 파일 트리 동시 변경에 대한 완전한 OS 격리는 제공하지 않습니다. 로컬 HTTP 설문 입력의 크기 제한은 검사할 파일·결과 수와 무관합니다.

외부 CVE DB 조회·침투 테스트·권한 검증·법률 인증·자동 비식별 변환은 하지 않습니다. 개인정보 최소 처리 완료 여부는 코드 검사와 설문만으로 확정하지 않으며 [검토 가이드](docs/GUIDELINES.md)의 증거가 필요합니다.

### 키 하드코딩·노출 검사

소스·JSON·`.env`·설정 파일·PEM/개인키 파일·빌드 번들·소스맵에서 주요 인증정보 형태와 비밀값 대입을 검사합니다. OpenAI 계열, GitHub, AWS, Google API, Stripe 비밀키, Slack, Supabase 비밀키 등의 형태, `OPENAI_API_KEY`·`AWS_SECRET_ACCESS_KEY`·`SUPABASE_SERVICE_ROLE_KEY`·`client_secret`·`jwt_secret` 등 변수명, 비밀번호가 포함된 접속 URL을 확인합니다. `NEXT_PUBLIC_`·`VITE_`·`REACT_APP_` 등의 공개 변수에 서버 비밀키를 넣는 패턴도 경고합니다. 결과에 키 값은 출력하지 않습니다.

공개용 anon/publishable/Firebase 설정은 서버 비밀키 유출로 단정하지 않고 권한·DB/RLS·API/출처 제한 검토를 안내합니다. 패턴 검사이므로 합성값·자리표시자도 탐지될 수 있고, 분할·암호화·난독화된 키나 알려지지 않은 형식은 놓칠 수 있습니다. 키 유효성을 확인하는 API 호출은 하지 않습니다.

**로컬에 값이 있는지 찾는 것과 인터넷에 실제 공개됐는지 확인하는 것은 다릅니다.** 이 도구는 대상 저장소의 공개 여부, Git 과거 이력, 배포 URL·CDN·캐시를 자동 조회하지 않습니다. 대상 저장소에도 Gitleaks 이력 검사와 GitHub 비밀 탐지/푸시 보호를 적용하고, 실제 배포물을 별도 점검해야 합니다. 이 도구 저장소의 CI는 이 도구 자체만 검사합니다. 실제 비밀키 노출이라면 삭제에 그치지 말고 폐기·재발급하세요.

Gitleaks가 Git 이력을 검사하며 원시 결과를 CI 로그나 아티팩트로 남기지 않습니다. Dependabot이 Actions와 npm 메타데이터를 관리합니다. 새 CVE와 고정 Gitleaks 버전은 지속적인 갱신이 필요합니다. **2026-11-07 기준 Node 11월 11일 보안 릴리스는 예정 상태**입니다. 릴리스 후 최신 패치를 적용하세요.

이 프로젝트는 `meta_harness`와 `dev-harness`의 학교 개인정보 지침과 검토 결과를 참고해 독립 구현했습니다. 실제 교사 앱이나 운영 학생 자료의 안전성을 이미 확인했다는 뜻은 아닙니다.
